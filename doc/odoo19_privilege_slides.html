What Is res.groups.privilege?

A New Intermediate Layer
in the Security Stack

Think of it as a named "role slot" — it sits between the App Category and the individual permission Groups, giving each section in the user form its own independent selection row.

🧩

Named Role Container

Groups are no longer directly attached to ir.module.category. They link to a res.groups.privilege which belongs to the category.

🎛️

Independent Selection Rows

Multiple privileges under one App means multiple radio-button rows in the user form — instead of one flat group list.

🔑

New privilege_id Field

res.groups gains a new privilege_id Many2one field in Odoo 19 that replaces the old direct category_id usage.

📐

Better RBAC Granularity

E.g. Accounting can now have a Core Accounting privilege AND a separate Bank Management privilege, each with own User/Admin levels.

❌ Odoo 18 — Old Approach

security.xml — Before

Groups directly reference category_id → ir.module.category. No Privilege layer exists.

<!-- 1. Define the Application Category -->
<record id="module_category_real_estate" model="ir.module.category">
    <field name="name">Real Estate</field>
    <field name="sequence">50</field>
</record>

<!-- 2. Groups directly use category_id (old) -->
<record id="estate_group_user" model="res.groups">
    <field name="name">Agent</field>
    <field name="category_id" ref="module_category_real_estate"/>  <!-- OLD -->
    <field name="implied_ids" eval="[(4, ref('base.group_user'))]"/>
</record>

<record id="estate_group_manager" model="res.groups">
    <field name="name">Manager</field>
    <field name="category_id" ref="module_category_real_estate"/>  <!-- OLD -->
    <field name="implied_ids" eval="[(4, ref('estate_group_user'))]"/>
</record>
⚠️ Problem: Only ONE radio-button row per App. You can't have separate "Accounting" + "Bank" sections inside the same category.

✅ Odoo 19 — New Approach

security.xml — After

Three-step definition: App Category → Privilege → Groups.

1
App Category (unchanged)
Still uses ir.module.category
2
Define Privilege NEW
Create res.groups.privilege record
3
Groups use privilege_id
Replace category_id with privilege_id
<!-- STEP 1: App Category (same as v18) -->
<record id="module_category_real_estate" model="ir.module.category">
    <field name="name">Real Estate</field>
</record>

<!-- STEP 2: Create the Privilege (NEW in v19!) -->
<record id="groups_privilege_real_estate"
        model="res.groups.privilege">
    <field name="name">Real Estate</field>
    <field name="sequence">50</field>
    <field name="category_id"
           ref="module_category_real_estate"/>
</record>

<!-- STEP 3: Groups use privilege_id (not category_id) -->
<record id="estate_group_user" model="res.groups">
    <field name="name">Agent</field>
    <field name="privilege_id"
           ref="groups_privilege_real_estate"/>
    <field name="implied_ids"
           eval="[(4, ref('base.group_user'))]"/>
</record>

<record id="estate_group_manager" model="res.groups">
    <field name="name">Manager</field>
    <field name="privilege_id"
           ref="groups_privilege_real_estate"/>
    <field name="implied_ids"
           eval="[(4, ref('estate_group_user'))]"/>
</record>

⚠️ Migration Guide

Migrating Custom Module
from Odoo 18 → Odoo 19

1️⃣
Keep ir.module.category
Your existing App category definition remains unchanged.
2️⃣
Add res.groups.privilege record
For each logical "role slot" your module had, create a privilege record with category_id pointing to your App.
3️⃣
Replace category_id with privilege_id
On every res.groups record, change category_id → privilege_id referencing your new privilege.
4️⃣
Update Python references
If your code accesses group.category_id, update to group.privilege_id.category_id.
# ── BEFORE (Odoo 18) ──────────────────
# security.xml snippet
<record id="my_group_user"
        model="res.groups">
  <field name="name">User</field>
  <field name="category_id"
         ref="my_module_category"/>
</record>


# ── AFTER (Odoo 19) ───────────────────
# ADDED: res.groups.privilege
<record id="my_privilege"
        model="res.groups.privilege">
  <field name="name">My Module</field>
  <field name="category_id"
         ref="my_module_category"/>
</record>

# CHANGED: privilege_id instead of category_id
<record id="my_group_user"
        model="res.groups">
  <field name="name">User</field>
  <field name="privilege_id"
         ref="my_privilege"/>
</record>

💡 Tip: You can still read group.category_id in Odoo 19 — Odoo auto-computes it from privilege_id.category_id for backward compatibility in some contexts. But always set privilege_id in XML.
